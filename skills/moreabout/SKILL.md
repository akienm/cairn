# /moreabout — the learning door

You are firing the **moreabout door**: a SCOPED expansion of something too
compressed, resolved from the upstream nexus's **already-deposited state** — a
walk, never a re-run — and the invocation itself is the training signal, written
back to that nexus's tree in the same act.

The device charter lives at `cairn/chart/intention+why.json` (falsifier 4 is this
skill's red line); this skill's charter beside this file.

ARGUMENTS: the thing to expand (the `<something>` of `/moreabout <something>`).

## 1. One command — the walk AND the signal

```bash
PYTHONPATH=$HOME/dev/src/cairn python3 -m cairn.chart.live moreabout '<the ask, verbatim>' [nexus] [owner]
```

Defaults walk chart's orient corpus. The door serves every tenant of the
generalized verbs through the same mouth:

- `moreabout '<ask>'` — chart's orient packets
- `moreabout '<ask>' corrections orient` — orient's correction scars
- `moreabout '<ask>' failures build_inspector` — the inspector's failure corpus

One embed serves both the walk and the write-back. The signal is **not
optional** — it fires inside the same command, because an opt-in signal would be
skipped exactly when the honest datum is least flattering.

## 2. Read the expansion honestly

- **Above-floor nodes** are candidates; when a node's provenance berths on disk,
  its full packet rides along under `berthed` — that is the deposited state you
  came for. A field you fill from it is provenance `tree`.
- **`under_floor: true`** — every node sits under the labeled floor, but the
  ranked nodes are still shown: ranking has been measured right under the floor
  (correct node first at 0.5775, 2026-07-28). You decide what applies. Never
  treat under-floor as "nothing known", and never fill the gap with a re-run.
- **An empty walk** is an honest answer: this class of ask has no deposit yet —
  and the signal that just landed IS the datum saying so.
- **`duplicate: true`** on the signal — this exact ask has signaled before.
  That is frequency, readable: the same field keeps coming up too compressed.

## 3. Answer from the walk

Report what the deposited state holds, with per-node similarity and provenance
visible. If the walk did not hold the answer, say so plainly — the honest next
move is the upstream stage running *forward* on new work (a fresh /chart), never
this door quietly re-running the old pass.

## Stay honest

- Never answer by re-running the upstream stage (charter falsifier 4 — and
  moreabout.py cannot reach that machinery by import physics; don't route
  around the physics by hand).
- The floor is a labeled n=1 guess; carry the label into your answer.
- The signal is the point as much as the answer: each invocation is a dated
  datum — "this, at this compression, wasn't enough" — that tunes the
  parsimony threshold on evidence.
